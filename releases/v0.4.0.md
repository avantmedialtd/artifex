af v0.4.0

Agents can now open what is attached to an issue or page, and editing text no longer deletes the images embedded in it. If your scripts update Jira descriptions or comments, check **Breaking changes** below.

## ✨ Highlights

- **Download Jira and Confluence attachments.** `af jira download <issue-key>` downloads every attachment of an issue, and `af jira download <id>…` downloads the ones you name. `af confluence download <page-id>` and `af confluence download <att-id>…` do the same for a Confluence page:

    ```bash
    af jira download PROJ-123 --name '*.png'   # only the PNGs (* and ? wildcards, case ignored)
    af jira download 10001 --out - | less      # one attachment on standard output
    ```

    Each run writes to a fresh folder in your temp directory and prints every file's full path. Downloads never land in your working tree, show up in `git status` or get committed by accident.

    Pass `--out <dir>` to keep the files somewhere else. A file already there with the same size is skipped. Any other existing file stops the run before anything is downloaded, unless you add `--force`. `--json` prints the folder and one entry per file.

- **See what is attached.** `af jira attachments <issue-key>` lists an issue's attachments with their IDs, sizes, types, dates and authors. `af jira get` now shows the same table, followed by the command that downloads them. `af confluence attachments` gains an ID column, so one file can be downloaded by ID.

- **Embedded images appear where they sit.** `af jira get`, `af confluence get` and the comment listings used to drop images pasted into a description, comment or page without a trace. They now show each image in place:

    ```
    **Screenshot:**

    ![screenshot.png](media:3f2a1c9e-8b4d-4e2a-9c7f-1d5e6b8a0c42)
    ```

    Attached files appear as `[name](media:…)`. To open one, download it by name with `af jira download <KEY> --name '<name>'`, or with `af confluence download` on a page.

## 🩹 Fixes

- **Editing text no longer deletes embedded images.** Reading an issue, editing its text and writing it back silently removed every embedded image. This affected `af jira update --description…`, `af jira comment edit` and `af confluence update`.
    - **Keep the line:** keep a `![…](media:…)` line and its image comes back exactly as it was, with the same size, layout and caption, even if you move the line.
    - **Delete the line:** the image leaves the text, and a warning names it. The attachment stays on the issue or page.

## ⚠️ Breaking changes

- **`af jira update --description…` and `af jira comment edit` read before they write.** Each makes one extra request for the current text, and prints a warning on standard error when the update removes an embedded image. The exit code and the `--json` output are unchanged.
- **`media:` references in markdown become images.**
    - `![name](media:<uuid>)` used to arrive as a link. It is now an embedded image.
    - Jira accepts only the issue's own attachments: a reference copied from another issue makes the update fail with HTTP 400.
    - `af jira create` cannot embed an existing file.

## 🔧 Improvements

- **The new commands reject options they don't know.** `af jira attachments`, `af jira download` and `af confluence download` exit `1` on an unknown flag, and suggest the one you probably meant.
- **Downloads are safe with files anyone can upload.**
    - Attachment names become plain filenames, so a name such as `../../.zshrc` still lands inside the download folder.
    - A file appears under its final name only once its size matches what Jira or Confluence reports.
    - Your credentials go only to your Atlassian site, never to the media servers that deliver the bytes.
- **Confluence images get names.** Confluence doesn't store an image's filename in the page. `af confluence get` looks the name up from the page's attachments, and only when it needs to.
