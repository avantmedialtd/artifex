af v0.1.0

The first tagged, automated release — published with provenance and real notes.

## ✨ Highlights

- **Resolve & reopen Bitbucket PR comment threads from the CLI** — `af bb pr comment resolve <pr> <cid>` and `reopen`, plus `comment list`/`get` now show each thread's resolution status. This closes the last gap between CLI- and UI-driven review (PR tasks already supported `--resolved`/`--unresolved`).
- **Automated, tag-driven releases** — `af` now ships through a `/release` flow and a CI workflow that publishes to npm with build provenance and cuts a GitHub Release from curated notes. This is the first release produced that way, so upgrades are now auditable and come with proper release notes.

## 🔧 Improvements

- **`af bb pr create` accepts `--source`/`--destination`** as aliases for `--from`/`--to`, matching the words the Bitbucket API, `git push`, and the web UI use. Previously those flags were silently ignored and the PR fell through to the default branch.

## 🩹 Fixes

- **`af e2e` no longer trusts a lying exit code** — the pass/fail verdict now cross-checks the bundled reporter's tally, so a swallowed or `|| true`-masked failure can't surface a false "✓ all passed" that `af stop-hook` would treat as green.
