af v0.2.0

Two new surfaces for agent-driven dev work: deep Jira workflow automation, and a read-only Bitbucket inspection layer that lets you read a remote repo without cloning it.

## ✨ Highlights

- **`af jira` grows real workflow depth** — transitions now carry their screens (`--resolution`, `--comment`, `--field`, with a 409 retry), so closing an issue sets the fields the workflow demands. Plus issue **move** across project/type, **reparent** via `--parent`, **async bulk** edit/transition/delete over a JQL selection, **worklogs** (add/list/update/delete), the **Agile API** (`rank`, sprint add/remove, board + sprint listing), and **watch/unwatch/vote**. An agent can now close, restructure, and schedule issues correctly instead of firing blind mutations.
- **`af bb` can read a remote repo without a clone** — a new read-only surface: `whoami`, `repo list/get`, `branch`/`tag list/get`, `commit list/get` (`--diff`/`--diffstat`/`--patch`), `src read`/`ls` (file content + directory browse at any ref), `diff <revspec>`, and PR gate state via `pr activity`, `pr status` ("is it green?"), and `pr reviewers --pending`. Every command supports `--json`. This fills the read half of the agent loop — orient, inspect, check the gate — that previously meant shelling out to `git` or the web UI.

## 🔧 Improvements

- **Jira comment management** — `comment edit`/`delete`, `--visibility` to restrict a comment to a role/group, and `--internal`/`--public` for JSM service-desk notes.
- **Discover before you mutate** — `af jira editmeta KEY` reports the editable fields and allowed values for an issue, and `af jira transitions KEY` now shows which transitions present a screen and what they require.
- **README rewritten** around the service-CLI / AI-agent framing, so the project reads as the agent-facing tool it has become.

## 🩹 Fixes

- **`af jira transition` no longer silently strips the resolution** — previously, transitioning to a state with a resolution screen (e.g. `--to Done`) posted only the transition id, leaving the issue resolved with **no Resolution** — silent workflow-state corruption. Transitions now send the resolution (and any comment/fields) the screen requires.
