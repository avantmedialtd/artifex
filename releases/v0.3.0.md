af v0.3.0

Markdown that agents write now arrives intact. Multi-line text goes in through a file or stdin, and Jira and Confluence bodies are converted by a real markdown parser. Check **Breaking changes** below before upgrading scripts.

## ✨ Highlights

- **Multi-line text from a file or stdin.** Every flag that takes prose now has a `-file` twin: `--body-file`, `--description-file` and `--comment-file`. Each takes a path, or `-` to read stdin, so a quoted heredoc arrives exactly as written:

    ```bash
    af jira comment PROJ-123 --body-file - <<'AF_BODY'
    ## Summary

    - First point
    AF_BODY
    ```

    This works for:
    - Jira comments, issue and version descriptions, and transition and worklog comments;
    - Confluence pages and comments;
    - Bitbucket pull request descriptions, comments and tasks.

    Inside quotes, the shell passes `\n` through as a backslash and an `n`, so `--add "## Summary\n\n- one"` posted one long heading with every `\n` visible. Double quotes also run `` `backticks` `` as commands and expand `$VARS` before `af` sees the text. `af` still sends inline text exactly as typed, so use a `-file` flag for anything longer than a line.

- **A real markdown parser for Jira and Confluence.** Comment, description and page bodies are now parsed as GitHub-flavored markdown by `marked`, a parser with no dependencies of its own, and mapped to Atlassian's document format. Syntax that used to arrive as literal text now renders:
    - code fences right after a line of text, inside list items, or fenced with `~~~`;
    - nested lists, and numbered lists that don't start at 1;
    - tables;
    - `~~strike-through~~`, `_italic_`, and formatting inside bold or link text;
    - links whose URL contains parentheses.

    In an audit of 66 snippets of typical agent-written markdown, the old converter got the block structure right in only 27. The new one converts all 66 as intended.

    Task lists become ☐ / ☑ bullets. Two behaviors are kept on purpose: a single newline is still a line break, and HTML-looking text such as `<ISSUE-KEY>` or `Promise<void>` stays as written.

- **`af jira get` and Confluence reads stop dropping content.** Text written in the Jira or Confluence editor keeps its mentions, emoji, smart links, dates, task items and expand titles, and tables and nested lists keep their shape.

## ⚠️ Breaking changes

- **Commands that take prose reject options they don't recognize.** These commands now exit `1` on an unknown option or a stray word, and suggest the flag you probably meant:
    - `af jira comment`, `create`, `update`, `transition`, `worklog`, `version-create` and `version-update`;
    - `af confluence create`, `update` and `comment`;
    - `af bb pr create`, `pr update`, `pr comment …` and `pr task …`.

    They used to ignore them: `af jira comment KEY --comment "…"` listed the comments, posted nothing and exited `0`. Now it fails with `Did you mean --body?`.

- **Empty bodies are errors.** An empty or whitespace-only comment or task body, or an empty file or stdin, now fails instead of posting an empty comment or creating an empty page.
- **`-` on a `-file` flag means stdin**, not a file named `-`.
- **`af confluence` rejects `--body` together with `--body-file`.** `--body` used to win silently.
- **Some markdown renders differently:**
    - `---` directly under a line of text turns that line into a heading, as on GitHub. Leave a blank line before `---` to get a horizontal rule.
    - Lines indented four spaces after a blank line become a code block.
    - `_x_` is italic, `~~x~~` is strike-through, and pipe tables become real tables.

## 🔧 Improvements

- **`af jira comment` and `af confluence comment` take `--body`**, the same flag as `af bb pr comment add`. `--add` still works as an alias.
- **Full help for each integration.** `af jira --help`, `af confluence --help` and `af bb --help`, and their `af help …` forms, now print the full reference with a heredoc example instead of a short summary. The Jira summary left out the `comment` subcommand entirely.
- **`--flag=value` works on every `af jira`, `af confluence` and `af bb` subcommand.**

## 🩹 Fixes

- **No more hangs on certain headings.** A heading marker with no text (`## `), or a heading in a file with Windows (CRLF) line endings, made Jira and Confluence commands run forever. Nothing was written, but the command never finished.
- **Empty list items and bare `>` lines no longer produce invalid documents.** They created empty text nodes, which Atlassian's document format forbids.
- **Windows line endings and byte-order marks are handled.** CRLF text no longer leaves stray carriage returns in comments, and a byte-order mark at the start of a file no longer turns its first heading into plain text.
- **A `|` in a worklog comment no longer breaks the `af jira worklog list` table.**
