af v0.3.1

Mark a Bitbucket draft ready for review without opening Bitbucket. If your scripts call `af bb pr update`, check **Breaking changes** below.

## ✨ Highlights

- **Mark a draft ready for review, or move it back to draft.** `af bb pr ready <id>` marks a draft ready for review, and `af bb pr draft <id>` turns an open pull request back into a draft. The same switches are `--ready` and `--draft` on `af bb pr update`, where they combine with `--title`, `--description` / `--description-file` and `--reviewers` in one request:

    ```bash
    af bb pr update 42 --description-file final.md --ready
    ```

    Bitbucket doesn't notify the reviewers of a draft until it is marked ready, so the whole draft workflow now runs from the terminal: open the pull request with `pr create --draft --reviewers …`, keep pushing, then run `pr ready` when it's done. Asking only for the state a pull request is already in prints a notice, changes nothing and exits `0`.

- **Drafts show up in `af bb pr list` and `af bb pr mine`.** A draft's State reads `OPEN (draft)`, as it already did in `pr get`. `--draft` keeps only drafts, and `--ready` keeps only pull requests that aren't drafts. Bitbucket applies the filter, so `--limit`, `--checks` and `--json` see only the matching pull requests.

## ⚠️ Breaking changes

- **`af bb pr update` reads the pull request before it writes.** That costs one extra request, and on a pull request that isn't open the command now fails without changing anything. Every update also sends the current title, description and reviewers for the fields you don't change, rather than leaving them out. If one of those reviewers is no longer active, Bitbucket rejects the update, and `af` suggests passing `--reviewers` with the reviewers to keep.
- **`af bb pr update <id>` with no change flag is an error.** It used to send an empty update.
- **`--reviewers ""` clears the reviewers.** It used to be ignored.
- **`--draft` on `af bb pr list` and `af bb pr mine` filters.** It used to be accepted and ignored.

## 🔧 Improvements

- **A failed `af bb pr merge` on a draft says why.** Bitbucket won't merge a draft, so `af` now says the pull request is a draft and names the fix: `af bb pr ready <id>`.
- **Bitbucket errors include their field-level details.** When Bitbucket answers with a bare message such as `Bad request`, the reasons it gives for each field are now printed underneath as `field: detail` lines, for every `af bb` command.
