af v0.2.3

See at a glance which of your pull requests need you.

## ✨ Highlights

- **Review state in `af bb pr mine` and `af bb pr list`.** Both tables have a new **Review** column. It shows:
    - approvals, such as `✓2`, not counting the author's own approval;
    - changes requested, such as `✗1`;
    - reviewers who haven't responded yet, such as `○1`.

    A new **Tasks** column shows how many tasks are still open.

    Bitbucket leaves reviewers out of pull request lists unless asked. `af` now asks for them in the list request it already makes, so this costs no extra API calls.

- **`--checks` for builds and conflicts.** Add `--checks` to either command to get two more columns for each open pull request:
    - **Builds** shows the build state of the latest commit, such as `✗ 1 failed`, `⟳ 2 running` or `✓ 3 passed`.
    - **Conflicts** shows `✓ none` or `✗ 2`.

    `--checks` is opt-in because it costs about three requests per open pull request. Merged and declined pull requests are skipped.

    These columns only report state. They never change the exit code. If Bitbucket won't return a signal, the cell shows `?` and one warning goes to stderr; the list still prints.

    `af` does not say whether a pull request is ready to merge. Bitbucket Cloud has no public API for merge checks, so `af` shows the signals they are built from instead.

## 🔧 Improvements

- **`--json` output of `pr mine` and `pr list` now includes `participants` and `reviewers`** on every pull request. Scripts can read approval state directly. Nothing else in the JSON changed, so existing scripts keep working.
